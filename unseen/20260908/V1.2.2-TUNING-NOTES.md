# v1.2.2 unseen tuning pass

Frozen unseen baseline (17 drives):
- Serial exact: 12/17 (70.6%)
- Model exact: 9/17 (52.9%)
- Manufacturer exact: 13/17 (76.5%)
- Drive type exact: 8/17 (47.1%)
- Capacity exact: 9/17 (52.9%)
- Processing errors: 0
- Incorrect serial automatically promoted to READY/CONFIRM: 0

Changes in the v1.2.2 candidate:
- Conservative model-as-serial rescue: if the current serial is a strong model/non-serial token, replace it only with the already-ranked top vendor-valid serial candidate at score >=100.
- Copies a recognized model-family token into Model before that rescue when Model is blank.
- Removes broad CA/CV/PH Lite-On family inference that could misclassify OEM part numbers; retains LJT/LCH Lite-On families.
- Tightens SK hynix HFM recognition to the structured HFM<capacity>GDJTNG8310A family and treats a visually separated trailing BA as label suffix rather than canonical model text.
- Adds SK hynix field-aware serial profile.
- Adds difficult-label RapidOCR label-union reread for missing S/N anchors.
- Adds difficult-label model reread when full and targeted model passes produce no candidate.
- Reconciles manufacturer from strong recovered model family.
- Adds exact family-derived drive type/capacity normalization for models exposed by the new 17-drive set.

Parser-only replay against the frozen v1.2.0 output (does not count the new fallback OCR reads) raises the deterministic floor to approximately:
- Serial 13/17 (76.5%)
- Model 11/17 (64.7%)
- Manufacturer 14/17 (82.4%)
- Drive type 13/17 (76.5%)
- Capacity 15/17 (88.2%)

The label-union rereads are expected to target the remaining difficult Samsung, SK hynix, HGST, SanDisk and WD cases, but those gains are not counted until an actual RapidOCR rerun is available.

Regression safety run #13 on the original 68-image corpus after the HFM/model-family changes:
- Selected model exact: 64/66 = 97.0%
- Corrected serial exact: 60/63 = 95.2%
- No regression from the frozen production candidate thresholds.
