# Camera Lab v1.2.1 unseen-validation change set

Baseline is frozen from v1.2.0 before any new-batch tuning. The 17-image unseen batch scored 12/17 exact serial (70.6%), 9/17 exact model (52.9%), 13/17 manufacturer, 0 processing errors, and 0 incorrect serials promoted to READY/CONFIRM.

## Production changes under test

- Reset all FieldReaderPrimary, SerialConsensus, and Knowledge per-image state inside Clear-DriveFields. The unseen CSV proved those values could leak from one image to the next.
- Expand manufacturer/model inference only for label families observed in the unseen set: Toshiba AL15, Fujitsu MAE/MAF/MAG, HGST HDS, Samsung MZVLW/MZJPV, SanDisk SD7SB3Q, SK hynix HFM, WD SDBQNTY/SDCPNRY, and Intel HBRPEKNX.
- Keep SK hynix HFM model length compatible with the existing known corpus (HFM + 14 characters). Normalize the unseen HFM O/0-vs-D OCR confusion only inside that constrained family.
- Prefer full-label WD SDBQNTY/SDCPNRY family identifiers over generic SN730/SN810 marketing anchors when the family identifier is actually present on the label.
- Normalize WD SDBQNTY 5120/512O to 512G only with 512 GB label evidence.
- When the current serial exactly equals the detected model, allow a valid RapidOCR S/N candidate to replace it. This addresses the unseen Toshiba model-as-serial failure without weakening generic serial gates.
- Preserve all existing safety behavior: ambiguous serials remain REVIEW; no generic numeric auto-promotion was added.

## Regression status

Known-corpus test run 34279489666 preserved serial at 60/63 (95.2%). The first experimental HFM length expansion reduced model from 64/66 to 63/66; that specific expansion was rejected. Production v1.2.1 keeps the original HFM length and applies a narrow HFM character correction instead.

The v1.2.1 lab package also contains the 17 new visually verified rows in Camera-Lab-Ground-Truth.csv so the same batch can be rerun with automatic scoring.
